# Workflow: brief to delivery

## 1. Intake

Capture the audience, job, surface/channel, desired response, required content,
technical limits, deadline, and approver. Mark assumptions rather than hiding
them.

## 2. Context inspection

Read the relevant brand rules and inspect adjacent product components/assets.
List what should be reused and what problem remains unsolved.

## 3. Brief

Create `work/briefs/YYYY-MM-DD-short-name.md` from the creative brief template.
Acceptance criteria must be observable: size, contrast, copy, states, file
format, responsive behavior, or test expectation.

## 4. Direction

For meaningful visual work, describe two or three distinct directions before
making. Compare them against the user job and brand principles, then choose one.
Do not create cosmetic variants that differ only in color.

## 5. Production

Create repository-native SVG/code where practical. Keep source editable,
semantic, and free of editor metadata. Reuse established tokens.

## 6. Review

Use `workflows/review.md` and save the result under `work/reviews/`. Resolve P0
and P1 findings before approval.

## 7. Delivery

Place approved artifacts in `work/deliverables/`, note intended destination and
usage, run validation, and summarize any unresolved follow-up.
